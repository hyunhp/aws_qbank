@ AIB-C01 D1 T1.1 applied comparison
S: A COO asks how machine learning differs from traditional software for automating loan pre-screening. Which explanation is most accurate?
A: Machine learning learns decision patterns from historical examples, while traditional software follows rules that people write explicitly
B: Machine learning always produces exact, repeatable answers, while traditional software makes probabilistic guesses about each applicant
C: Machine learning needs no data to operate once installed, while traditional software needs large datasets before it can make decisions
D: Machine learning can only run on premises, while traditional software can only run on cloud infrastructure in regulated industries
K: A
W: Traditional programs apply explicit rules; machine learning infers patterns from examples, which suits problems where rules are hard to write down.
X: B=It is the reverse: rule-based code is deterministic, and ML outputs are probabilistic. | C=ML depends on data to learn. | D=Both run in either environment.
T: Rules are written for traditional software; patterns are learned by machine learning.

@ AIB-C01 D1 T1.1 advanced use-case

B: A feature is a new capability added to the retailer's website, such as a wish list or a gift card option

D: A feature is the algorithm that was selected for the project, such as a decision tree or a neural network

W: In machine learning, features are the input variables describing each example; the model learns how they relate to the outcome.

@ AIB-C01 D1 T1.1 applied use-case
S: A logistics firm's model predicts delivery delays with 90% accuracy, but 95% of deliveries are on time. Why should leadership be cautious about the 90% figure?
A: A model that always predicts 'on time' would score 95%, so accuracy alone hides how well delays are caught
B: Accuracy above 85% is always suspicious and usually means the model was trained on test data
C: Delivery data changes daily, so any accuracy figure becomes meaningless within the first 24 hours after training
D: 90% accuracy guarantees that 90% of late deliveries will be detected before customers complain
K: A
W: With imbalanced outcomes, accuracy can look good while the model misses most of the rare but important cases. Recall and precision on delays tell the real story.
X: B=High accuracy is not inherently suspicious. | C=Performance can drift, but it does not vanish daily. | D=Accuracy is not recall on the late class.
T: With rare events, judge models on how well they catch those events, not on overall accuracy.

@ AIB-C01 D1 T1.3 advanced comparison
S: A leadership team is choosing how to adapt a foundation model. Which statement correctly compares prompt engineering and fine-tuning?
A: Prompt engineering changes the input and is fast to iterate; fine-tuning changes model weights and needs data and training
B: Prompt engineering permanently retrains the model; fine-tuning only changes the wording of each request
C: Prompt engineering requires thousands of labeled examples; fine-tuning works without any training data at all
D: Prompt engineering and fine-tuning are the same technique, described differently by different vendors
K: A
W: Prompt engineering shapes behavior through the input, so it is quick and cheap to change; fine-tuning adjusts the model with training data, which costs more but can embed consistent behavior.
X: B=The descriptions are reversed. | C=Fine-tuning needs data; prompting does not. | D=They are distinct techniques.
T: Try prompting first; fine-tune when you need consistent behavior that prompts cannot achieve.

@ AIB-C01 D1 T1.3 applied use-case
S: A company's assistant must answer questions about data in a large internal database, such as 'total sales by region last quarter.' Which approach is most reliable?
A: Have the model generate a database query, run it against the database, and summarize the actual results
B: Ask the model to estimate the sales totals from its general training data and present them as facts
