@ AIB-C01 D3 T3.2 advanced definition
S: Auditors ask for continuously collected evidence that the AWS resources behind the company's AI workloads comply with its internal configuration controls, grouped by control set and with each resource's compliance history over time. Which AWS service fits?
A: Amazon Inspector
B: AWS Trusted Advisor
C: AWS Artifact
D: AWS Config rules
K: D
G: ## Continuous compliance evidence on AWS
**AWS Config** records the configuration of AWS resources, keeps a timeline of every change, and evaluates resources against **rules** that express your controls, for example "S3 buckets holding training data must block public access" or "SageMaker notebook instances must not have direct internet access".
- A **conformance pack** bundles a set of rules and remediation actions into one deployable unit, so a whole control set (a standard or your internal controls) can be applied across accounts and Regions with AWS Organizations.
- For every resource and rule, Config records compliant or noncompliant results over time, which gives auditors ongoing evidence instead of point-in-time screenshots.
- Results can be aggregated across accounts and exported or queried for audit reports.
## Where Audit Manager fits
AWS Audit Manager used to be the usual answer for control-mapped audit evidence, but it has been closed to new customers since April 30, 2026; AWS points new users to AWS Config conformance packs, whose rule evaluations were already one of Audit Manager's evidence sources.
W: AWS Config: its rules and conformance packs continuously evaluate the AI workloads' resources against the internal controls, grouped by control set, and it keeps each resource's configuration and compliance history as ongoing evidence.
X: A=Amazon Inspector: it scans EC2 instances, container images and Lambda functions for software vulnerabilities and network exposure; it does not evaluate resources against your own control set or keep compliance history per control.
B=AWS Trusted Advisor: it runs AWS-defined best-practice checks for cost, security and service limits, but you cannot load your internal controls into it, and it does not keep a per-resource compliance timeline.
C=AWS Artifact: it provides AWS's own compliance reports and agreements, such as SOC and ISO reports, which describe AWS's controls, not evidence about the customer's own workloads.
T: Customer-side, continuously recorded compliance evidence against your own controls comes from AWS Config and conformance packs; AWS's own compliance reports come from Artifact.
V: AWS Config
