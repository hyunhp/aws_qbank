# AIF-C01 batch 12: responsible AI development (D4 T4.1)

@ AIF-C01 D4 T4.1 applied troubleshooting
S: A retrieval-augmented support assistant built on Amazon Bedrock sometimes answers with confident details that appear nowhere in the retrieved company documents. The team wants to catch these unsupported answers before they reach customers. Which Amazon Bedrock Guardrails capability fits?
A: A contextual grounding check comparing each response with the source passages
B: A denied topic listing every product and service name that the company does not sell
C: A profanity word filter that blocks a managed and custom list of offensive terms
D: A prompt attack filter that detects jailbreak attempts to override system instructions
K: A
G: ## Hallucination in a RAG application
A model can produce fluent text that is not backed by the documents it was given. This is called a hallucination, and in a support setting it hurts veracity (truthfulness) and customer trust.
## What Guardrails offers
Amazon Bedrock Guardrails is a set of configurable safeguards applied to both user inputs and model outputs. Different policies address different risks:
- **Content filters** block categories such as hate, insults, sexual content, violence and misconduct.
- **Denied topics** block subjects you define in natural language.
- **Word filters** block exact words or phrases.
- **Sensitive information filters** detect or mask personal data.
- **Contextual grounding check** scores whether a response is grounded in the supplied source and relevant to the query, and blocks responses under a threshold you set.
W: Contextual grounding check: it is built for RAG and summarization, where the retrieved passages are the source of truth. It flags answers that add facts not present in those passages or that drift away from the question, and you choose the score threshold that triggers blocking.
X: B=Denied topic: a denied topic stops a whole subject from being discussed. It does not verify whether a permitted answer matches the retrieved documents.
C=Word filter: it matches exact strings such as profanity. An invented but polite sentence contains no blocked words, so it passes through.
D=Prompt attack filter: it defends against jailbreaks and prompt injection in user input. The problem here is unsupported content in the output, not malicious input.
T: Answers that must stay faithful to source documents call for the contextual grounding check; other guardrail policies handle topics, words, personal data and attacks.
V: Amazon Bedrock

@ AIF-C01 D4 T4.1 applied comparison
S: A chatbot team must stop the assistant from ever mentioning three named competitor brands in its replies, whatever the phrasing of the question. They want the simplest exact-match control. Which Amazon Bedrock Guardrails feature should they configure?
A: Word filters containing the three brand names
B: A contextual grounding check with a high threshold
C: A sensitive information filter with a regex pattern
D: Content filters set to their highest strength
K: A
G: ## Choosing the right guardrail policy
Guardrails policies overlap only a little, so match the policy to the kind of risk.
- **Word filters** work on exact words and phrases you list, such as brand names or profanity.
- **Denied topics** cover broader subjects described in natural language, such as "investment advice".
- **Content filters** classify harmful categories such as hate or violence by strength.
- **Sensitive information filters** detect personal data types or custom regular expressions.
## Fit for this case
The requirement is a fixed list of known strings, which is exactly the job of word filters.
W: Word filters: you enter the competitor names once and any prompt or response containing them is blocked, which is precise and needs no natural-language topic definition.
X: B=Contextual grounding check: it measures whether an answer is supported by source text. It has no notion of brand names.
C=Sensitive information filter with regex: it is meant for personal data patterns such as account numbers, and brand names are not personal data, so it is the wrong tool even though a pattern could technically match.
D=Highest-strength content filters: they target harm categories such as hate and violence. A polite sentence naming a competitor is not harmful content, so it would still pass.
T: A fixed list of forbidden strings means word filters; a whole subject means denied topics; harm categories mean content filters.
V: Amazon Bedrock

@ AIF-C01 D4 T4.1 applied use-case
S: A healthcare startup uses a foundation model to summarize patient call transcripts. Summaries must never show patient names or phone numbers, but the clinical details must stay readable. Which Amazon Bedrock Guardrails setting best meets this need?
A: Sensitive information filters set to mask the name and phone number entity types
B: A denied topic named patient information, with a short natural-language description
C: Content filters for sexual and violent content set to high strength
D: A contextual grounding check with the score threshold set to zero
K: A
G: ## Privacy as a responsible AI feature
Privacy means personal data is collected, used and exposed only as intended. Generative models can repeat personal data that appears in prompts or context, so protection is added at the input and output boundary.
## Sensitive information filters
Guardrails can detect predefined personally identifiable information (PII) types such as names, phone numbers and email addresses. For each type you choose an action: block the whole request or response, or mask the value with a placeholder so the rest of the text is kept.
W: Masking the name and phone number types keeps the summary useful, because only those values are replaced by placeholders while the clinical content stays intact.
X: B=Denied topic: a topic blocks the discussion as a whole, so useful summaries would be refused, and a natural-language description is less reliable than entity detection for names and numbers.
C=Content filters: sexual and violent categories do not relate to personal identifiers, so names and numbers would pass unchanged.
D=Threshold of zero: a grounding check tests support from source text, not privacy, and a threshold of zero would block almost nothing anyway.
T: Use sensitive information filters to mask or block PII; masking preserves the surrounding useful text.
V: Amazon Bedrock

@ AIF-C01 D4 T4.1 applied definition
S: Before training a loan-approval model, a team wants a report showing whether the labeled training data already favors one demographic group, such as a much smaller share of approved outcomes for one group. Which AWS capability provides this kind of pre-training analysis?
A: Amazon SageMaker Clarify bias metrics computed on the dataset
B: Amazon SageMaker Model Cards documenting intended use and known model limitations
C: Amazon SageMaker Role Manager persona-based permission templates for ML teams
D: Amazon SageMaker Model Monitor data quality baselines for live endpoint traffic
K: A
G: ## Bias can enter before any model exists
If historical data reflects unequal treatment or under-represents a group, a model trained on it tends to repeat that pattern. Detecting this early is cheaper than fixing a deployed model.
## Where Clarify fits
Amazon SageMaker Clarify computes bias metrics at two points:
- **Pre-training**, on the dataset alone, for example class imbalance between groups or differences in the share of positive labels.
- **Post-training**, on model predictions, for example differences in accuracy or approval rates between groups.
It also produces feature attributions to explain predictions.
W: Clarify's pre-training bias metrics analyze the dataset itself, so imbalances in group representation and labels appear before any training cost is spent.
X: B=Model Cards: a card documents intended use, data and limits and is not an analysis tool. It records findings but does not compute bias metrics.
C=Role Manager: it builds least-privilege IAM permissions for ML personas. It has nothing to do with data fairness analysis.
D=Model Monitor baselines: these watch data quality and drift on live endpoints, and they compare with a baseline rather than test a group balance in a labeled training set.
T: Clarify detects bias in data before training and in predictions after training, and explains feature influence.
V: Amazon SageMaker

@ AIF-C01 D4 T4.1 applied troubleshooting
S: A retailer's product recommendation model passed a fairness review at launch. Six months later, customer demographics have shifted and the team fears new bias. They want scheduled checks on the live endpoint that compare current behavior against the launch baseline and raise alerts. Which AWS capability fits?
A: Amazon SageMaker Model Monitor with bias drift monitoring
B: Amazon Augmented AI human review workflows for every prediction
C: Amazon Bedrock model evaluation using a curated prompt dataset
D: Amazon SageMaker Ground Truth labeling jobs for incoming new data
K: A
G: ## Responsible AI is not finished at launch
Bias and quality can change after deployment because real-world data drifts away from the training data. A model that was fair at launch can become unfair without any code change.
## Continuous monitoring
Amazon SageMaker Model Monitor runs scheduled monitoring jobs on endpoint traffic and compares them with a baseline. It covers data quality, model quality, feature attribution drift and bias drift, and it can publish alerts through Amazon CloudWatch.
W: Model Monitor's bias drift monitoring, built on Clarify metrics, repeatedly compares live traffic with the baseline captured at launch and alerts when group-level results move, which is exactly the ongoing check requested.
X: B=Augmented AI: it adds human reviewers for selected predictions. It is a review step, not a scheduled comparison of group-level behavior against a baseline.
C=Bedrock model evaluation: it assesses foundation models on prompt datasets, typically when choosing or tuning a model. It does not monitor a deployed SageMaker endpoint's live traffic.
D=Ground Truth: it produces labeled data for training. Labeling new data does not measure bias drift on live predictions.
T: Use Model Monitor (with bias drift) for scheduled comparisons of live behavior against a launch baseline.
V: Amazon SageMaker

@ AIF-C01 D4 T4.1 applied use-case
S: An insurance company uses an ML model to flag claims for fraud. It wants a person to examine a claim only when the model's confidence is low, and also to review a small random sample of confident decisions to audit quality. Which service supports both review triggers?
A: Amazon Augmented AI (Amazon A2I) human review workflows
B: Amazon SageMaker Clarify feature attribution reports
C: AWS Glue DataBrew data profiling jobs
D: Amazon SageMaker Model Cards approval workflows
K: A
G: ## Humans in the loop
Some decisions are too consequential or uncertain for full automation. Human oversight keeps people able to correct the system and catches errors that automation misses, which supports safety and trust.
## Amazon A2I
Amazon Augmented AI lets you define a human review workflow. You set conditions, for example a prediction confidence below a threshold, that send an item to reviewers. You can also route a random percentage of predictions for review to audit performance. Reviewers can be your own employees, a private workforce, or a vendor. A2I integrates with services such as Amazon Textract and Amazon Rekognition and with custom ML models.
W: A2I: it supports both a confidence-based trigger and random sampling, sends the item to a human workforce, and returns the reviewers' decisions for use or for retraining.
X: B=Clarify feature attribution: it explains which inputs influenced a prediction. It does not route items to people.
C=DataBrew profiling: it inspects dataset quality before use and has no role in reviewing live predictions.
D=Model Cards: a card documents a model for governance, but it does not create a review queue for individual claims.
T: Use A2I to add human review for low-confidence predictions and for random quality audits.
V: Amazon Augmented AI

@ AIF-C01 D4 T4.1 advanced tradeoff
S: A marketing team is choosing between two foundation models on Amazon Bedrock for writing campaign copy. The main quality criterion is whether the writing sounds on-brand and emotionally appropriate, which no automatic score captures well. Which evaluation approach is most suitable?
A: A human-based evaluation where the team's reviewers rate sample responses
B: An automatic evaluation using only accuracy against a labeled answer key
C: A single prompt tested once by the lead developer without a rating scale
D: Reusing the model provider's published benchmark results without new testing
K: A
G: ## Ways to evaluate a foundation model
Amazon Bedrock model evaluation supports several styles:
- **Automatic evaluation** uses built-in datasets and metrics such as accuracy, robustness and toxicity.
- **LLM-as-a-judge evaluation** uses another model to score responses on dimensions such as correctness, completeness and harmfulness, which scales cheaply.
- **Human evaluation** uses your own workforce or an AWS-managed team to rate responses on criteria you define, such as style, friendliness or brand voice.
## Choosing
Subjective qualities such as tone are judged best by people who know the brand. Automatic scores are faster and repeatable but only measure what they are designed to measure.
W: Human-based evaluation lets the team's own reviewers rate each model on brand voice with a consistent rating method, and that judgment is the criterion that matters here.
X: B=Accuracy on an answer key: campaign copy has no single correct answer, so an accuracy score does not reflect tone or brand fit.
C=One untracked prompt: a single trial is not a representative sample, and without a rating scale the impression is neither repeatable nor comparable.
D=Published provider benchmarks: they describe general capabilities, not the team's own prompts, audience and brand style.
T: Subjective qualities such as tone call for human evaluation; automatic and LLM-judge evaluation suit scalable, well-defined metrics.
V: Amazon Bedrock

@ AIF-C01 D4 T4.1 advanced use-case
S: A publisher plans to use a generative AI image tool for magazine covers. Legal counsel worries about intellectual property claims. Which TWO actions best reduce this legal risk? (Select TWO)
A: Review the model provider's terms on training data sources and any IP protection offered
B: Have people check outputs for resemblance to protected works before publication
C: Add a footer saying all images are generated by AI so the copyright question no longer applies
D: Increase the image resolution so outputs differ more from any training image
E: Prompt the model to imitate specific living artists to keep the style familiar
K: A,B
G: ## Legal risks of generative AI
Generative models can reproduce or closely resemble material they were trained on, which can lead to intellectual property (IP) and copyright infringement claims. Other legal and business risks include biased outputs, hallucinated statements, harm to end users and loss of customer trust.
## Reducing IP risk
The risk cannot be removed by labeling or by technical tweaks alone. Practical controls are understanding where the model's training data came from and what the provider promises, and adding human review before publication.
W: A=Provider due diligence: the terms show what data trained the model and whether the provider offers IP protection, which addresses the source of the risk.
B=Human output review: people catch look-alike content before publication, which addresses the final product.
X: C=AI disclosure footer: telling readers an image is generated is good for transparency but it does not prevent or excuse infringement.
D=Higher resolution: resolution changes image quality, not whether the content resembles a protected work.
E=Imitating living artists: this increases the chance of outputs that copy a distinctive protected style and invites disputes.
T: Manage generative AI IP risk with due diligence on the provider and training data plus human review of outputs; disclosure alone is not protection.

@ AIF-C01 D4 T4.1 applied troubleshooting
S: A demand-forecasting model scores poorly on both its training data and on new data. It is very simple and uses only two input features. What is the most likely problem and fix?
A: Underfitting; use a more expressive model or add informative features
B: Overfitting; add more layers so the model learns the training set better
C: High variance; shrink the training dataset to reduce noise
D: Data leakage; remove the test set so scores improve
K: A
G: ## Bias and variance in plain terms
- **Bias** is error from a model that is too simple to capture real patterns. It shows as poor performance on both training and new data, which is called **underfitting**.
- **Variance** is error from a model that is too sensitive to the specific training examples. It shows as excellent training results but much worse results on new data, which is called **overfitting**.
## Why it matters for responsible AI
A biased (underfit) model can be systematically wrong, and it is often worst for groups whose patterns differ from the majority. A high-variance model can be unreliable and inconsistent across groups.
W: Poor scores on training and new data together, with a very simple model, point to underfitting. More expressive models, more informative features or longer training let it learn the real pattern.
X: B=Overfitting with more layers: overfitting means good training results and bad new-data results, which is not what is observed here.
C=High variance with less data: variance problems appear as a large train-versus-new-data gap, and less data usually makes overfitting worse, not better.
D=Data leakage and removing the test set: leakage inflates scores instead of lowering them, and deleting the test set removes the way to measure quality.
T: Poor on both training and new data means underfitting (high bias); great on training but poor on new data means overfitting (high variance).

@ AIF-C01 D4 T4.1 applied use-case
S: A team building a chatbot for financial guidance wants to train on public text and considers scraping all posts from open internet forums. Which approach to selecting this dataset best supports responsible AI?
A: Use curated, reviewed sources, filter toxic text, and document each source
B: Take the largest possible volume of raw posts because more data removes bias
C: Use only the most popular posts because popularity signals correctness
D: Use posts from a single forum so the writing style stays uniform
K: A
G: ## Responsible dataset selection
The data a model learns from shapes what it says. Responsible selection looks at:
- **Quality and curation**: trusted, reviewed sources with errors and toxic content filtered out.
- **Diversity and inclusivity**: enough variety in people, languages, and viewpoints so the model works for everyone it serves.
- **Balance**: no group is overwhelmingly over- or under-represented.
- **Provenance and licensing**: knowing where data came from and whether it may be used.
W: Curated and filtered sources reduce harmful and inaccurate content, and documenting provenance supports licensing checks, audits and transparency.
X: B=Volume above all: raw data can carry toxicity, errors and skew, so more of it can amplify bias rather than remove it.
C=Popularity as a signal: popular posts are not necessarily accurate, and financial advice in particular can be popular and wrong.
D=Single forum for uniformity: one community narrows the range of people and viewpoints, which reduces diversity and inclusivity.
T: Choose curated, filtered, diverse and documented data; volume alone does not guarantee fairness or quality.

@ AIF-C01 D4 T4.1 advanced use-case
S: A dataset for a loan model contains 10,000 records from applicants in urban areas and only 400 from rural areas, and the model performs worse for rural applicants. Which TWO actions best address the imbalance? (Select TWO)
A: Collect additional representative data from rural applicants
B: Use resampling or reweighting so the rural group carries more influence during training
C: Drop the rural records entirely so the data is consistent
D: Remove the location field and assume the model can no longer be unfair
E: Report only overall accuracy so the gap stays out of the results
K: A,B
G: ## Imbalanced data and unfair performance
When a group is under-represented, the model has few examples to learn from and tends to be less accurate for it. This is one of the most common sources of unfair outcomes.
## Ways to respond
- **Collect** more representative data so the group is genuinely covered.
- **Rebalance** with oversampling, undersampling or example weights so a small group is not drowned out.
- **Evaluate by subgroup** rather than only overall, so gaps become visible.
W: A=Collect more data: it fixes the root gap by adding real examples of the under-represented group.
B=Resample or reweight: it compensates for the remaining imbalance so the model learns patterns for the smaller group.
X: C=Dropping the rural group: the model then knows nothing about that group and will likely perform even worse for it while excluding it from the service.
D=Removing the location field: other features can still act as proxies for location, and the imbalance is unchanged.
E=Overall accuracy only: a large majority hides the gap, and reporting only the average is the opposite of subgroup analysis.
T: Fix imbalance by collecting representative data and rebalancing; always evaluate performance per subgroup.

@ AIF-C01 D4 T4.1 applied troubleshooting
S: Reviewers suspect that crowd annotators labeled sentiment inconsistently, with different people giving the same review different labels. The model trained on these labels performs erratically. Which step best addresses the root cause?
A: Audit a sample of labels, measure annotator agreement, and relabel disagreements
B: Increase the number of training epochs so the model averages out the labeling noise across annotators
C: Switch to a much larger model so it can learn and reproduce each annotator's personal style
D: Delete the validation set so that the noisy labels no longer affect the reported scores
K: A
G: ## Label quality
Supervised models learn whatever the labels say. Inconsistent or biased labels teach inconsistent or biased behavior, and no algorithm choice fully repairs that.
## How to check label quality
- **Human audits** examine a sample of labels against guidelines.
- **Agreement measures** compare annotators on the same items; low agreement shows unclear guidelines or careless work.
- **Correction** relabels disputed items, often using several annotators per item and a review step.
W: Auditing and measuring agreement finds where labels conflict, and correcting them repairs the data itself, which is where the erratic behavior originates.
X: B=More epochs: extra training makes the model fit the noisy labels more closely instead of fixing them.
C=Larger model: extra capacity increases the ability to memorize noise and does not add consistency.
D=Deleting the validation set: this only hides the symptom by removing the measurement, and the labels stay wrong.
T: Noisy labels need label quality analysis: audit samples, check annotator agreement and relabel.

@ AIF-C01 D4 T4.1 applied comparison
S: A team reviews three quality problems. Problem 1: a model's answers contain invented facts. Problem 2: a model's accuracy collapses when input images are slightly blurred. Problem 3: a model gives dangerous instructions to users. Which mapping to responsible AI features is correct, in order?
A: Veracity, robustness, safety
B: Robustness, safety, veracity
C: Safety, veracity, robustness
D: Fairness, privacy, explainability
K: A
G: ## Three features that are easy to confuse
- **Veracity**: outputs are truthful and factually correct. Invented facts, or hallucinations, break veracity.
- **Robustness**: the model stays reliable when inputs are noisy, unusual or slightly changed.
- **Safety**: the system does not cause harm to people, for example by giving hazardous instructions.
- **Fairness**, **privacy** and **explainability** address equal treatment of groups, protection of personal data, and understanding of decisions.
W: Invented facts are a veracity failure, a collapse under blurred inputs is a robustness failure, and dangerous instructions are a safety failure.
X: B=Robustness, safety, veracity: this assigns each label to the wrong problem, for example calling invented facts robustness, when input stability is what robustness measures.
C=Safety, veracity, robustness: it shifts every label one place, so invented facts are called safety and blur sensitivity is called veracity, and neither matches those definitions.
D=Fairness, privacy, explainability: none of the three problems concerns unequal group treatment, personal data or decision explanations.
T: Truthful is veracity, stable under changed inputs is robustness, and not causing harm is safety.

@ AIF-C01 D4 T4.1 advanced use-case
S: A voice assistant recognizes speech accurately for the team's own developers but frequently fails for customers with regional accents and older speakers. Which TWO actions best improve inclusivity? (Select TWO)
A: Add training and test data that represent many accents, ages and speaking conditions
B: Measure accuracy separately for each accent and age group before release
C: Tune the model only on the developers' recordings so results become consistent
D: Publish only the overall word error rate for the whole user base
E: Tell affected customers to speak more like the developers
K: A,B
G: ## Inclusivity
An inclusive AI system works well for the full range of people who will use it, including different accents, ages, languages, abilities and backgrounds. Failures for some groups usually trace back to data that did not represent them.
## What helps
- **Representative data** for training and testing, so every group is seen by the model.
- **Subgroup analysis**, meaning metrics broken out by group, so that gaps are visible instead of averaged away.
W: A=Representative data: it removes the cause of the gap by letting the model learn from every accent and age group.
B=Per-group measurement: it shows whether the gap has actually closed before release.
X: C=Tuning only on developer recordings: this narrows the data further and makes the model even worse for other accents and ages.
D=Overall error rate only: a single average hides that certain groups do much worse.
E=Asking customers to change: this puts the burden on users, and it is the opposite of designing the system to serve them.
T: Inclusivity comes from representative data and per-group evaluation, not from asking users to adapt.
