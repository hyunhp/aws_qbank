G: ## Auditing who called an AWS API
AWS CloudTrail records API activity in your account. Each event says **who** made the call (the IAM user or role), **when**, from which source IP, which API was called and whether it succeeded.
- Calls to Amazon Bedrock, such as `InvokeModel`, `Converse` or `CreateModelCustomizationJob`, are recorded as management events, which CloudTrail captures by default. Some Bedrock runtime operations, such as calls to agents and knowledge bases, are data events that you turn on for a trail.
- Event history keeps the last 90 days of management events at no charge; a trail delivers events to Amazon S3 for long-term retention and analysis.
## Example
An auditor asks who invoked a model at 02:00 last night. A CloudTrail query shows the event name, the role `arn:aws:iam::111122223333:role/chat-app` and the exact timestamp.
CloudTrail records call metadata, not the full prompt and response text; that is what Bedrock model invocation logging is for.
W: AWS CloudTrail: it is the service that logs API calls with the caller identity, time and parameters, which is exactly a record of who called Bedrock and when.
X: A=AWS Trusted Advisor: it checks your account against best practices for cost, security, performance and limits; it does not record individual API calls.
B=Amazon Inspector: it scans EC2 instances, container images and Lambda functions for software vulnerabilities and network exposure; it keeps no log of who called which API.
D=AWS Config: it records how resource configurations change over time and evaluates them against rules; it tracks resource state, not a per-call history of model invocations.
T: "Who called which API and when" is CloudTrail; Config tracks resource configuration, and Trusted Advisor and Inspector give recommendations and vulnerability findings.

G: ## Capturing prompts and responses in Bedrock
**Model invocation logging** is an Amazon Bedrock setting that records the request and response of each model invocation in the account and Region.
- It is off by default; you enable it and choose Amazon S3, Amazon CloudWatch Logs or both as destinations.
- Each record contains the input (the prompt), the output (the model's response) and metadata such as the model ID, token counts and the calling identity.
- Large payloads and binary data such as images can be delivered to S3.
## Why it matters
Stored prompts and responses let a team review answers for quality, investigate a harmful output or build evaluation datasets. Because the logs can contain sensitive user data, the destination bucket or log group should be encrypted and access-restricted.
Example: a support chatbot logs to CloudWatch Logs, and reviewers search for conversations where users reported a wrong answer.
W: Bedrock model invocation logging: it is built to capture the full input and output of every model call and deliver them to S3 or CloudWatch Logs for later review.
X: A=AWS Config rules: Config evaluates resource settings such as encryption or tags; it never sees the text that flows through a model call.
C=CloudTrail management events: CloudTrail records that an API call happened, who made it and when, but it is not designed to store the complete prompt and response bodies.
D=Amazon Inspector findings: Inspector reports software vulnerabilities in the Lambda code and its dependencies; it has no view of the prompts and responses the application exchanges.
T: To keep the actual prompts and responses, enable Bedrock model invocation logging; CloudTrail only shows that the call was made.

G: ## Protecting AI data in two states
Data needs protection both where it is stored and while it moves.
- **At rest**: training datasets in S3, custom model artifacts and vector stores are encrypted on disk. AWS Key Management Service (AWS KMS) manages the keys; a customer managed key gives you control over its key policy and rotation, and every use of a KMS key is logged in CloudTrail.
- **In transit**: calls to AWS service endpoints, including Amazon Bedrock and SageMaker, use TLS so data cannot be read or altered on the network. Bucket policies can require it with the condition `aws:SecureTransport`.
## Example
A team stores fine-tuning data in an S3 bucket encrypted with a KMS key, allows only the training role to use the key, and calls Bedrock over HTTPS from its application.
Encryption works together with least-privilege IAM, private buckets and audit logging; the other listed practices remove those protections.
W: D=Encrypt at rest with AWS KMS: stored training data and model artifacts stay unreadable without permission to use the key, and every key use is auditable.
E=Encrypt in transit with TLS: data moving between clients and AWS endpoints is protected from interception and tampering on the network.
X: A=Publicly readable bucket: anyone on the internet could download the training data, which is a data exposure, not a protection.
B=Shared IAM access keys: shared long-term credentials remove accountability and are hard to rotate; each person or workload should use its own identity, ideally temporary role credentials.
C=Disable CloudTrail: turning off logging removes the audit trail needed to detect and investigate misuse; it weakens security to save a small cost.
T: Protect AI data with KMS encryption at rest and TLS in transit; public buckets, shared keys and disabled logging all increase risk.

G: ## Data residency on AWS
An AWS Region is a physical location, and data you store in a Region stays there unless you or a service feature you enable moves it. That makes the Region choice the main data residency control.
- Keep training data, models and logs in a Region located in the required country.
- Prevent use of other Regions with a service control policy that denies requests using the `aws:RequestedRegion` condition key, and leave opt-in Regions you do not need disabled.
- Review features that copy data elsewhere, such as S3 Cross-Region Replication, cross-Region backups or Bedrock cross-Region inference, which can route requests to other Regions.
## Example
A company that must keep data in Japan stores datasets in the Tokyo Region and applies an SCP that denies actions requested in any other Region.
W: Use Regions in that country and restrict the others: data stays in the chosen Region, and a Region restriction stops anyone from creating copies or resources elsewhere.
X: B=Cheapest storage Region: price says nothing about location; the cheapest Region may be in another country, breaking residency.
C=Lowest-latency Region per user: serving users worldwide from their nearest Region spreads data across many countries, the opposite of residency.
D=Replicate to every Region: copying data to all Regions maximizes availability but places it outside the required country.
T: Data residency is enforced by choosing in-country Regions and blocking the rest; cost, latency and availability choices can move data abroad.

G: ## Data poisoning
A model learns whatever patterns its training data contains. **Data poisoning** is an attack where someone inserts, alters or mislabels training records so the trained model behaves the way the attacker wants.
- The effect may be broad (lower overall accuracy) or targeted, such as a hidden trigger phrase that makes the model produce a chosen output.
- It is a risk wherever data comes from sources the company does not fully control: web scrapes, user submissions, third-party datasets or fine-tuning data.
## Defenses
- Restrict write access to training data and log changes with CloudTrail.
- Track data provenance and lineage, validate data before training, and look for anomalies or outliers.
- Evaluate models on trusted test sets before deployment.
Example: an attacker submits many fake reviews labeling a scam product as positive, and a model retrained on them starts recommending it.
W: Data poisoning: deliberately inserting malicious records into training data to manipulate the model is the definition of this risk.
X: A=Model hallucination: hallucination is a model generating confident but false content; it arises from how models generate text, not from an attacker tampering with training data.
B=Concept drift: drift is the real-world relationship between inputs and outcomes changing over time, which degrades a model without any attacker involved.
D=Prompt leaking: prompt leaking is when a user tricks a deployed model into revealing its hidden system prompt or instructions; it happens at inference time, not in the training data.
T: Tampering with training data is poisoning; prompt leaking and injection attack the model at inference time.

G: ## Data governance for AI training data
Data governance defines how data is collected, used, kept and deleted, and who is accountable for it. For AI it answers "what data trained this model, and were we allowed to use it?"
- **Retention**: set how long each dataset may be kept based on legal and business needs, then delete it on schedule. S3 Lifecycle expiration rules can automate deletion.
- **Lineage**: record where data came from and every transformation applied, so any model can be traced back to its sources. SageMaker ML Lineage Tracking and the data lineage feature of Amazon DataZone help with this.
- **Access control and cataloging**: restrict who can read or copy datasets, for example with AWS Lake Formation permissions.
## Example
When a customer asks for their data to be deleted, lineage shows which datasets and models used it, and the retention policy ensures old copies are already gone.
W: B=Retention periods with deletion on expiry: keeping data only as long as needed meets legal obligations and reduces the amount of data at risk.
E=Track data lineage: tracing data from source through transformations makes models auditable and lets teams find affected data when a problem appears.
X: A=Skip documenting sources: undocumented sources make it impossible to prove the company had the right to use the data or to trace issues back.
C=Keep data forever: indefinite retention can violate laws that limit how long personal data may be kept and increases exposure if the data is breached.
D=Copy to personal accounts: uncontrolled copies escape access controls, logging and deletion policies, which defeats governance entirely.
T: Good AI data governance means knowing where data came from (lineage) and keeping it only as long as allowed (retention).

G: ## Guardrails for a whole organization
A **service control policy (SCP)** in AWS Organizations sets the maximum permissions for accounts in an organizational unit. An SCP never grants access; it limits what IAM policies in member accounts can allow, even for administrators.
- To restrict Regions, an SCP denies actions when the `aws:RequestedRegion` condition key is not in an approved list.
- It can target a single service, for example denying `bedrock:*` outside `us-east-1` and `eu-west-1`.
- SCPs do not apply to the management account, so workloads should run in member accounts.
## Example
A security team attaches an SCP to the Workloads OU that denies Bedrock actions in all other Regions. A developer in a member account who tries to invoke a model in an unapproved Region gets an access denied error.
W: Service control policy: it centrally enforces a deny across member accounts, so Bedrock cannot be used outside approved Regions no matter what local IAM policies allow.
X: B=S3 lifecycle rule: lifecycle rules move or expire objects in a bucket; they cannot block API calls in any Region.
C=Tag on each Bedrock model: a tag is only a label; it blocks nothing by itself, and it cannot stop a call made in an unapproved Region.
D=CloudWatch dashboard: a dashboard shows usage after it happens; it provides visibility, not prevention.
T: Preventing actions across an organization is an SCP; dashboards and tags only show or label what happens.

G: ## Keeping personal data out of AI responses
**Amazon Bedrock Guardrails** apply configurable safeguards to model inputs and outputs. The **sensitive information filters** handle personally identifiable information (PII).
- Built-in PII types include names, email addresses, phone numbers, addresses and national ID numbers; custom regular expressions cover company-specific patterns such as account numbers.

An HR assistant is asked about a colleague, and the model's draft reply includes a phone number. The guardrail masks the number before the response reaches the user.

T: PII in outputs is controlled with Guardrails sensitive information filters; inference settings such as temperature, length or model size do not filter content.

G: ## Learning without labels
Machine learning types differ by what the training data tells the model.
- **Supervised learning** uses labeled examples (input plus the correct answer).
- **Unsupervised learning** uses unlabeled data and finds structure on its own, such as groups of similar items (clustering) or unusual points (anomaly detection).
- **Reinforcement learning** learns actions from rewards and penalties.
## Clustering example
A retailer feeds each customer's purchase frequency, average basket size and product categories into an algorithm such as k-means. It returns groups like "frequent low spenders" and "occasional big spenders". Nobody labeled these segments in advance; the algorithm discovered them, and marketers name them afterward.
W: Unsupervised learning: grouping customers by behavior without predefined labels is clustering, the classic unsupervised task.
X: A=Supervised learning: supervised models need labeled examples of the right answer, and here there are no predefined segments to learn from.
B=Transfer learning only: transfer learning reuses a model pretrained on one task for another; it is a technique for reusing knowledge, not the method that discovers groups in unlabeled data.
C=Reinforcement learning: it learns a sequence of actions from rewards in an environment; segmenting a static customer dataset involves no actions or rewards.
T: No labels and a goal of finding groups means unsupervised clustering; supervised learning needs known answers.

G: ## Reinforcement learning
In **reinforcement learning (RL)**, an **agent** takes actions in an **environment**, observes the result and receives a **reward** or penalty. Over many trials it learns a **policy**, a strategy for choosing actions, that maximizes total reward.
- No one gives the correct action for each situation; the agent discovers good behavior by trial and error.
- It suits sequential decisions: robotics, games, routing and resource scheduling.
## Example
A warehouse robot gets +10 for reaching a pick location, -50 for hitting a shelf and -1 for every second spent. Early on it moves randomly; after many simulated runs it learns short, collision-free paths. RL training usually happens in simulation before the policy is used on real hardware.
W: Reinforcement learning: learning a navigation strategy from rewards for reaching goals and penalties for collisions is exactly how an RL agent is trained.
X: A=Supervised learning: it would require labeled examples of the correct move in each situation; here the robot only gets rewards after acting.
B=Unsupervised learning: it finds structure in unlabeled data, such as clusters; it does not learn actions from rewards and penalties.
D=Self-supervised learning: it creates labels from the data itself, such as predicting a masked word, which is how foundation models are pretrained; it involves no rewards from an environment.
T: Rewards and penalties for actions mean reinforcement learning; supervised learning needs labeled correct answers.

@ Q002518 explain
G: ## Matching the metric to the task
The first question is what the model outputs.
- **Regression** predicts a continuous number: a price, a temperature, a demand quantity.
- **Classification** predicts a category: fraud or not fraud, cat or dog.
- **Clustering** groups unlabeled data without a correct answer.
## Regression metrics
**RMSE (root mean squared error)** measures the typical size of prediction errors in the same units as the target. It squares errors before averaging, so large misses count heavily. MAE and R-squared are other regression metrics.
Example: if predicted prices are off by $10,000, $20,000 and $30,000, the RMSE is about $21,600, which is easy to explain to the business.
Accuracy, recall and AUC count right and wrong categories, so they only make sense for classification.
W: Regression with RMSE: a house price is a continuous value, and RMSE measures how far predicted prices are from actual prices in dollars.
X: A=Classification with recall: recall measures how many actual positives were found in a category task; a price is not a category.
C=Classification with AUC: AUC measures how well a model ranks positive cases above negative ones for binary classification; it cannot score a numeric price prediction.
D=Clustering with accuracy: clustering finds groups without labels and does not predict a target value, and accuracy is a classification metric that needs known correct classes.
T: Predicting a number is regression, measured with errors like RMSE; recall, AUC and accuracy belong to classification.

G: ## Overfitting and underfitting
A model should learn general patterns that also hold for new data.
- **Overfitting**: the model memorizes the training data, including its noise. Training performance is very high, but performance on validation or new data is much lower.
- **Underfitting**: the model is too simple or undertrained to capture the patterns, so it performs poorly on both training and new data.
## Reading the numbers
99% on training data versus 70% on new data is a large gap, and the gap is the signature of overfitting. An underfit model would score low on the training data too.
## Common fixes
- More, or more varied, training data and data augmentation.
- Regularization, dropout or a simpler model.
- Early stopping when validation performance stops improving.
- Cross-validation to measure generalization honestly.
W: Overfitting: excellent training accuracy combined with much worse accuracy on unseen data shows the model memorized the training set instead of generalizing.
X: A=Bias-free, well-balanced model: a 29-point drop on new data shows a serious generalization problem, not a well-balanced model.
B=Too little training time: undertraining causes underfitting, which would show low accuracy on the training data as well, not 99%.
D=Underfitting: underfitting means the model cannot even fit the training data; 99% training accuracy rules it out.
T: High training score with low test score is overfitting; low scores on both is underfitting.

G: ## When machine learning is the right tool
ML learns patterns from examples and produces probabilistic predictions. It shines when the rules are too complex to write by hand and some errors are acceptable.
## Good fits
- Complex patterns, such as spotting fraud across hundreds of signals.
- Plenty of relevant historical data to learn from.
- Predictions that improve decisions even if they are sometimes wrong, such as recommendations.
## Poor fits
- The answer is fully defined by a known formula or rule, such as calculating sales tax or payroll deductions. Ordinary code gives an exact, explainable, cheap and always-correct answer.
- Little or no data, or a need for 100% deterministic results with no tolerance for error.
Example: a tax calculator with an ML model could return $102.37 when the law gives exactly $100.00; a single line of code would never make that mistake.
W: Fixed, fully specified formula: when the correct answer is determined by a known rule, ML only adds cost and error; deterministic code is simpler and exact.
X: B=Complex patterns hard to express as rules: this is the classic case where ML adds value, because it learns the patterns that people cannot write down.
C=Large amounts of historical data: plentiful relevant data is what ML models need to learn, so this makes ML a better fit, not a worse one.
D=Predictions help and some errors are tolerable: ML predictions are probabilistic, so tolerance for occasional errors is a condition for a good fit.
T: If a fixed formula already gives the right answer, use code, not ML; ML is for complex patterns learned from data.

G: ## The ML lifecycle in order
A typical ML project moves through these phases:
- Define the business problem and success metric.
- Collect data from relevant sources.
- Prepare data and engineer features.
- Train candidate models.
- **Evaluate** each candidate on held-out validation or test data it never saw during training.
- Deploy the chosen model.
- Monitor it in production, then retrain or retire it when performance drops or it is no longer needed.
## Why evaluation follows training
Training performance alone is misleading because a model can memorize its training data. Evaluation on held-out data estimates real-world performance and lets you compare candidates against the business metric before anything is deployed.
Example: two churn models both score 95% on training data, but on held-out data one reaches 88% and the other 74%, so only the first moves on to deployment.
W: Evaluating on held-out data: after training, each candidate must be measured on unseen data to check it generalizes before deployment.
X: A=Defining the business problem: this is the very first step and must happen before any data is collected or any model is trained.
C=Retiring the production model: retirement happens at the end of a model's life after it has been deployed and monitored, not right after training.
D=Collecting raw data sources: data collection happens before training, because training needs the prepared data.
T: Train, then evaluate on held-out data, then deploy; the business problem and data collection come before training, retirement at the end.

G: ## Watching models in production
Models are trained on past data, but the world changes. When input data or the relationship between inputs and outcomes shifts, accuracy slowly declines; this is called **drift**.
**Amazon SageMaker Model Monitor** watches deployed endpoints and batch transform jobs on a schedule.
- **Data quality**: compares live input statistics to a baseline built from training data.
- **Model quality**: compares predictions to actual outcomes (ground truth labels) to track metrics such as accuracy.
- **Bias drift** and **feature attribution drift**, using SageMaker Clarify.
Violations are published to Amazon CloudWatch, where alarms can trigger an alert or a retraining pipeline.
## Example
A churn model's accuracy slips from 90% to 78% over six months as customers shift to a new plan. Model Monitor detects the drop and alerts the team to retrain.
W: SageMaker Model Monitor: it continuously compares production data and prediction quality against a baseline and flags drift as customer behavior changes.
X: B=SageMaker Ground Truth: Ground Truth creates labeled datasets with human and automated labeling; it does not monitor deployed models.
C=SageMaker JumpStart: JumpStart offers pretrained models and solution templates to get started quickly; it has no production monitoring role.
D=SageMaker Canvas: Canvas lets business analysts build models without code; it is not the tool that watches a deployed endpoint for drift.
T: Declining accuracy after deployment is drift, detected with Model Monitor; the other tools help build or label, not monitor.

G: ## No-code ML for business analysts
**Amazon SageMaker Canvas** lets people without coding or ML experience build models and generate predictions through a point-and-click interface.
- Import data from a CSV file, Amazon S3, Redshift or other sources.
- Pick the target column, such as `churned`, and Canvas detects the problem type, here binary classification.
- Choose a quick build for a fast estimate or a standard build for higher accuracy; Canvas handles data preparation, algorithm selection and tuning.
- Review accuracy and which columns most influence predictions, then run single or batch predictions or share the model with data scientists.
