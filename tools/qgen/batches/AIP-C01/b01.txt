# AIP-C01 batch 01: Domain 1 (requirements analysis, FM selection and configuration)
@ AIP-C01 D1 T1.1 advanced use-case
S: A bank wants a GenAI assistant for loan officers. Requirements: answers must cite internal policy, data must stay in eu-central-1, and p95 latency must stay under three seconds. Which design decision should be made first?
A: Confirm which models and features are available in eu-central-1 that meet the latency target
B: Select the model with the highest public benchmark score and then check the Region later
C: Fine-tune a model on all loan policies before confirming where it can be deployed
D: Build the user interface first and choose the model after the pilot has launched
K: A
W: Residency and latency are hard constraints. Checking Regional availability and latency of candidate models first prevents building on an option that cannot be deployed.
X: B=Benchmarks do not satisfy residency or latency constraints. | C=Fine-tuning before confirming deployability risks wasted effort. | D=Deferring model choice ignores hard constraints.
T: Start GenAI design from hard constraints such as residency and latency.
V: Amazon Bedrock

@ AIP-C01 D1 T1.1 advanced tradeoff
S: A company must choose between a single large model for all tasks or routing simple queries to a small model and complex ones to a large model. Traffic is 80% simple FAQs. Which design is most cost-effective without hurting quality?
A: Route by query complexity so most traffic uses the smaller model
B: Send every query to the largest model to maximize answer quality
C: Send every query to the smallest model and accept lower quality
D: Alternate models randomly for each query to balance the load
K: A
W: Routing lets the majority of simple traffic use a cheaper, faster model while complex queries still get a capable model.
X: B=Using the largest model for FAQs wastes cost. | C=Complex queries would suffer. | D=Random alternation ignores complexity.
T: Route by complexity to balance cost and quality.

@ AIP-C01 D1 T1.2 advanced use-case

B: Deploy the same app in a second account in us-east-1
C: Switch to a model with a larger context window
D: Increase max tokens so fewer requests are needed
