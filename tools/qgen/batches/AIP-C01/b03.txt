# AIP-C01 batch 03: Domain 1 (retrieval mechanisms, prompt engineering and governance)
@ AIP-C01 D1 T1.5 advanced use-case
S: A RAG system retrieves 20 candidate chunks, but the most relevant ones are often ranked low and cut off. Which addition improves answer quality?
A: A reranker model that reorders candidates by relevance before generation
B: Increasing the chunk size so fewer, larger chunks are retrieved for each question
C: Lowering the generation temperature so the model focuses on the first chunks
D: Removing metadata from the chunks so the vector search has fewer fields to use
K: A
W: Rerankers score query-document relevance more precisely than vector similarity alone, improving which chunks reach the model.
X: B=Larger chunks dilute relevance. | C=Temperature does not change retrieval order. | D=Removing metadata reduces filtering options.
T: Improve retrieval ordering with a reranker.
V: Amazon Bedrock Knowledge Bases

@ AIP-C01 D1 T1.5 applied use-case
S: Users search a legal knowledge base using exact clause numbers such as 'Section 14.3(b)', which vector search often misses. Which retrieval approach fits?
A: Hybrid search combining keyword and semantic matching
B: Pure semantic search with a larger embedding model
C: Random sampling of chunks from the whole corpus
D: Increasing max output tokens for the final answer
K: A
W: Keyword matching catches exact identifiers that semantic embeddings can blur; hybrid search combines both.
X: B=Semantic search still blurs exact identifiers. | C=Random sampling is not retrieval. | D=Output length is unrelated to retrieval.
T: Exact identifiers need keyword matching → hybrid search.

@ AIP-C01 D1 T1.5 advanced tradeoff

A: More chunks can improve recall but add cost, latency, and irrelevant context
B: More chunks always improve accuracy with no effect on cost or latency
C: Fewer chunks always improve accuracy because models prefer short prompts
D: The number of chunks has no measurable effect on answer quality at all
K: A
W: Top-k balances recall against token cost, latency, and distraction from irrelevant context; it should be tuned with evaluation.
X: B=More chunks increase tokens and latency. | C=Too few chunks can miss needed information. | D=Chunk count affects quality.
T: Tune top-k by measuring quality, cost, and latency.
