# AIP-C01 batch 05: Domain 2 (implementation and integration)
@ AIP-C01 D2 T2.1 applied use-case
S: An agent built with Amazon Bedrock Agents must look up order status through an internal REST API. How should the API be exposed to the agent?
A: As an action group defined by an OpenAPI schema backed by a Lambda function
B: As a knowledge base data source that indexes the API's JSON responses nightly
C: As text pasted into the agent's instructions listing every possible order state
D: As a guardrail policy that blocks questions about orders the API cannot answer
K: A
W: Action groups describe callable operations (via OpenAPI or function schemas) and invoke Lambda or return control to the app.
X: B=Indexing responses gives stale data, not live calls. | C=Instructions cannot fetch live status. | D=Guardrails filter content, not call APIs.
T: Agents call APIs through action groups.
V: Amazon Bedrock Agents

@ AIP-C01 D2 T2.1 advanced use-case
S: An agent must pause before issuing a refund so the client application can collect user confirmation and execute the API itself. Which Bedrock Agents feature fits?
A: Return of control to the application for the action
B: A higher temperature for the agent's orchestration
C: A knowledge base attached to the refund action group
D: A longer session timeout configured for the agent
K: A
W: Return of control sends the chosen action and parameters to the application, which can confirm with the user and run it.
X: B=Temperature does not add confirmation. | C=Knowledge bases provide information, not control. | D=Timeouts do not add a confirmation step.
T: Let the app confirm and execute with return of control.
V: Amazon Bedrock Agents

@ AIP-C01 D2 T2.1 applied use-case

@ AIP-C01 D2 T2.2 advanced use-case
S: A GenAI endpoint receives sporadic traffic with long idle periods and large payloads that take minutes to process. Which SageMaker option reduces cost?
A: Asynchronous inference with scale to zero
B: Real-time inference with a fixed fleet
C: Multi-model endpoint with GPUs always on
D: Serverless inference with 6 MB payloads
K: A
W: Asynchronous inference queues requests, handles large payloads and long processing, and can scale to zero when idle.
X: B=A fixed fleet costs money while idle. | C=Always-on GPUs cost money while idle. | D=Serverless inference has payload and duration limits.
T: Long, large, sporadic requests → asynchronous inference.

@ AIP-C01 D2 T2.2 applied use-case

A: Deployment guardrails with canary traffic shifting
B: A single endpoint update with all-at-once traffic
C: Manual creation of a new endpoint every release
D: A notebook that calls both endpoints for users
K: A
W: Deployment guardrails shift traffic gradually (canary or linear) and roll back on CloudWatch alarms.
X: B=All-at-once exposes all users to a bad version. | C=Manual endpoints lack automatic rollback. | D=Notebooks are not traffic management.
T: Safe model rollouts → deployment guardrails.
V: Amazon SageMaker AI

@ AIP-C01 D2 T2.3 applied use-case
S: A company wants a GenAI service to react to events from many internal systems, such as new tickets or orders, without tight coupling. Which pattern fits?
A: Event-driven integration with Amazon EventBridge routing events to consumers
B: Direct synchronous calls from each system to the GenAI service on every change
C: A shared database table that every system polls every few seconds for changes
D: A nightly batch file transfer from each system to the GenAI service over FTP
K: A
W: EventBridge decouples producers and consumers and routes events by rules, supporting scalable, loosely coupled integration.
X: B=Synchronous calls couple systems tightly. | C=Polling is inefficient and couples through a table. | D=Nightly batches add delay.
T: Decouple integrations with event-driven patterns.

@ AIP-C01 D2 T2.4 advanced troubleshooting
S: An application receives ThrottlingException errors from Bedrock during bursts. Which TWO changes help most? (Select TWO)
A: Retry with exponential backoff and jitter
B: Buffer requests in a queue and control the send rate
C: Retry immediately in a tight loop until success
D: Increase max tokens so fewer calls are needed
E: Switch every call to synchronous batch inference
K: A,B
W: Backoff with jitter spreads retries, and queuing smooths bursts to stay within limits.
X: C=Tight loops worsen throttling. | D=Longer outputs do not reduce calls. | E=Batch inference is not synchronous and does not serve interactive calls.
T: Handle throttling with backoff and buffering.
V: Amazon Bedrock, Amazon SQS

@ AIP-C01 D2 T2.5 advanced use-case
S: Thousands of documents arrive in bursts and must each be summarized by a model within an hour. Which TWO design choices fit? (Select TWO)
A: Queue documents in SQS and process them with scalable workers
B: Control worker concurrency to stay within model throughput limits
C: Call the model synchronously from the upload request handler
D: Process all documents in a single long-running request
E: Drop documents that arrive during peak bursts
K: A,B
W: Queues absorb bursts, and controlled concurrency keeps calls within throughput limits while meeting the deadline.
X: C=Synchronous calls in the upload path fail under bursts. | D=One long request is fragile. | E=Dropping documents loses data.
T: Buffer bursts and pace model calls.
V: Amazon SQS, AWS Lambda

@ AIP-C01 D2 T2.2 advanced tradeoff
S: A company hosts dozens of small fine-tuned variants of the same base model, each with light traffic. Which hosting approach is most cost-effective?
A: Serve adapters on a shared endpoint, such as multi-adapter or inference components
B: Deploy each variant on its own always-on GPU endpoint
C: Run each fine-tuned variant on its own separate Lambda function using only CPU resources
D: Merge all variants into one prompt and use a base model
K: A
W: Sharing a base model and loading adapters per request consolidates many light-traffic variants onto fewer instances.
X: B=Dedicated GPUs per variant waste capacity. | C=Lambda lacks GPUs for these models. | D=Prompt merging does not reproduce fine-tuned behavior.
T: Consolidate many small variants on shared endpoints.
V: Amazon SageMaker AI
