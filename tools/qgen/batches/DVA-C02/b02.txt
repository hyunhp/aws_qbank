# DVA-C02 batch 02: Domain 2 (security)
@ DVA-C02 D2 T2.1 applied use-case
S: A mobile app needs users to sign in with email and password or Google, then call an API Gateway API. Which component authenticates users?
A: An Amazon Cognito user pool with a Cognito authorizer on the API
B: IAM users created for every mobile app customer who signs up
C: An API key issued to each user and embedded in the mobile app
D: A security group that allows traffic from mobile networks only
K: A
W: Cognito user pools handle sign-up, sign-in, and social identity providers, and Cognito authorizers validate their tokens.
X: B=IAM users do not scale to app users. | C=API keys are not user authentication. | D=Security groups do not authenticate users.
T: App user authentication → Cognito user pools.
V: Amazon Cognito, Amazon API Gateway

@ DVA-C02 D2 T2.2 applied use-case
S: A developer must encrypt a 50 MB file with a KMS key. The KMS Encrypt API rejects the request. Why, and what should be done?
A: Encrypt accepts at most 4 KB; use envelope encryption with GenerateDataKey
B: The KMS key is disabled; enable it and retry the same Encrypt request
C: The file must be uploaded to S3 before KMS can encrypt it directly
D: KMS only encrypts text, so the file must be converted to base64 first
K: A
W: KMS Encrypt handles up to 4 KB; larger data uses envelope encryption with a data key.
X: B=The failure is due to size, not the key state. | C=S3 upload is not a KMS requirement. | D=Encoding does not change the size limit meaningfully.
T: Large data → envelope encryption with data keys.

@ DVA-C02 D2 T2.3 advanced use-case
S: An application reads many configuration values and a few secrets at startup, and cost matters. Which approach fits?
A: Parameter Store for configuration, with SecureString for secrets that do not need rotation
B: Secrets Manager for every configuration value, regardless of sensitivity or rotation needs

@ DVA-C02 D2 T2.2 advanced use-case
S: Which TWO statements about envelope encryption with KMS are correct? (Select TWO)
A: GenerateDataKey returns plaintext and encrypted copies of a data key
B: The encrypted data key is stored alongside the encrypted data
C: The KMS key itself is downloaded to encrypt large files locally
D: The plaintext data key should be stored permanently with the data
E: KMS Encrypt should be called directly for multi-gigabyte files
K: A,B
W: Data is encrypted locally with the plaintext data key, which is then discarded; the encrypted data key is stored with the data for later decryption by KMS.
X: C=KMS keys never leave KMS. | D=Plaintext data keys should not be stored. | E=Encrypt is limited to 4 KB.
T: Envelope encryption: encrypt locally, store the encrypted data key.
V: AWS KMS
