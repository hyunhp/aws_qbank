# DVA-C02 batch 07: last four
@ DVA-C02 D3 T3.1 applied use-case
S: A developer wants a CloudFormation template to reference a value created in another stack in the same Region, such as a VPC ID. Which functions fit?
A: Export the value as an output and use Fn::ImportValue in the other stack
B: Hard-code the VPC ID copied from the console into the second template
C: Use Fn::GetAtt on a resource that only exists in the first stack
D: Use Ref with the logical ID of the resource defined in the other stack
K: A
W: Cross-stack references use exported outputs and Fn::ImportValue.
X: B=Hard-coded IDs break when resources change. | C=GetAtt works only within the same template. | D=Ref works only within the same template.
T: Share values across stacks with exports and ImportValue.
V: AWS CloudFormation

@ DVA-C02 D3 T3.2 advanced use-case
S: A developer wants to test an application's integration with SQS and DynamoDB in a CI pipeline without affecting production resources. Which approach fits?
A: Deploy temporary test resources in a separate account or stack for the pipeline run
B: Point the integration tests at the production queue and table to use real data
C: Skip integration tests and rely only on unit tests with mocked dependencies
D: Run the integration tests manually on a developer laptop against production
K: A
W: Isolated, temporary test resources allow real integration tests without production impact.
X: B=Testing against production risks data. | C=Mocks miss integration issues. | D=Manual production tests are risky.
T: Integration tests need isolated environments.
V: AWS CloudFormation

@ DVA-C02 D3 T3.4 applied use-case
S: A team wants Elastic Beanstalk to deploy new application versions to a percentage of instances in batches while maintaining capacity. Which policy fits?
A: Rolling with additional batch
B: All at once
C: Rolling without extra batch
D: Manual in-place update
K: A
W: Rolling with additional batch launches extra instances so full capacity is maintained during batches.
X: B=All at once causes downtime. | C=Plain rolling reduces capacity during batches. | D=Manual updates are error-prone.
T: Batch deployments without capacity loss → rolling with additional batch.
V: AWS Elastic Beanstalk

@ DVA-C02 D3 T3.3 advanced use-case
S: A pipeline must automatically roll back a CloudFormation stack update if it fails partway. What provides this behavior?
A: CloudFormation's automatic rollback on update failure
B: A manual approval action after deployment finishes
C: An S3 lifecycle rule on the pipeline's artifacts
D: A CodeBuild phase that deletes the stack on errors
K: A
W: CloudFormation rolls back to the previous state when a stack update fails, by default.
X: B=Approval does not roll back. | C=Lifecycle rules manage artifacts. | D=Deleting stacks is destructive, not a rollback.
T: CloudFormation rolls back failed updates automatically.
V: AWS CloudFormation
