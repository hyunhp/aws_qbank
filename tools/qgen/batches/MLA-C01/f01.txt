S: Traffic to a SageMaker real-time endpoint rises sharply, and auto scaling is slow to add capacity that can serve requests. Which TWO actions get new, ready-to-serve instances in place sooner? (Select TWO)
A: Use a scaling policy with a suitable cooldown and target
B: Disable health checks on the endpoint entirely
C: Store the model artifact in S3 Glacier Deep Archive
D: Package every unused dependency into the container
E: Use smaller model artifacts and optimized containers
K: A,E
G: ## What happens during endpoint scale-out
When traffic rises, new capacity for a SageMaker endpoint is not available immediately. The delay has two parts:
- **Deciding to scale**: the alarm must fire on the scaling metric and the policy must decide to add instances. The target value and cooldown settings control how early and how often this happens.
- **Making an instance ready**: SageMaker launches the instance, pulls the container image from ECR and downloads the model artifact from S3. The container then loads the model into memory and must answer the `/ping` health check before it receives traffic.
Both parts can be shortened. A target and cooldown that let scaling react earlier start new capacity sooner; a smaller artifact and a lean, optimized image download and load faster on each new instance.
## Example
A 12 GB artifact and a 9 GB image take minutes to load per new instance. Compressing the model and removing unused libraries cuts that time sharply, and a lower target value starts scale-out before latency climbs.
W: A=Tuned scaling policy: a suitable target and cooldown make the policy start adding instances earlier and without needless waiting, so new capacity is ready sooner after traffic rises.
E=Smaller artifacts and optimized containers: less to download and load means each new instance passes its health check and starts serving traffic faster.
X: B=Disable health checks: SageMaker health checks cannot be turned off, and they exist so that traffic only reaches containers that have actually loaded the model.
C=Glacier Deep Archive for artifacts: objects in Deep Archive must be restored before they can be read, which takes hours, so a new instance could not load the model at all.
D=Package unused dependencies: extra libraries make the image larger, so pulling and starting it on each new instance takes longer, not shorter.
T: Scale-out speed depends on how early scaling triggers and how quickly each new instance can download and load the model; bigger images or archived artifacts slow it down.
