# SAA-C03 batch 01: Domain 1 (secure architectures)
@ SAA-C03 D1 T1.1 applied use-case
S: A web application on EC2 needs to upload files to one specific S3 bucket. What is the most secure way to grant access?
A: An IAM role attached to the instance with a policy allowing PutObject on that bucket only
B: An IAM user's access keys stored in the application's configuration file on the instance
C: A bucket policy that allows public write access so the application can upload files
D: The root user's access keys set as environment variables on each application server
K: A
W: Instance roles provide temporary credentials, and a scoped policy grants only the needed action on the specific bucket.
X: B=Stored long-term keys can leak. | C=Public write is insecure. | D=Root credentials must never be used for applications.
T: Use IAM roles with least-privilege policies for workloads.
V: AWS IAM, Amazon S3

@ SAA-C03 D1 T1.1 advanced use-case
S: A mobile app must let users upload photos directly to S3 without routing files through backend servers, and without embedding AWS credentials in the app. Which solution fits?
A: Generate short-lived presigned URLs from the backend for each upload
B: Embed an IAM user's access keys in the mobile application package
C: Make the bucket publicly writable so any user can upload directly
D: Share the root account password with the mobile development team
K: A
W: Presigned URLs grant time-limited permission for a specific upload without exposing credentials.
X: B=Embedded keys can be extracted. | C=Public write allows abuse. | D=Root credentials must never be shared.
T: Direct client uploads → presigned URLs.
V: Amazon S3

@ SAA-C03 D1 T1.1 applied use-case
S: A company wants its employees to sign in to AWS accounts using existing corporate identities from its identity provider. Which service fits?
A: AWS IAM Identity Center federated with the corporate identity provider
B: IAM users created manually for every employee in every one of the company's accounts
C: Amazon Cognito identity pools for employee console access
D: A shared IAM user whose password is given to all employees

T: Workforce federation → IAM Identity Center.
V: AWS IAM Identity Center

@ SAA-C03 D1 T1.1 advanced use-case
S: Users of a web application must sign up, sign in, and use social logins, and the app then needs temporary AWS credentials to access S3. Which combination fits?
A: Cognito user pools for authentication and identity pools for AWS credentials
B: IAM users created for every application user, each with an individual password
C: A custom user table in RDS with passwords stored in plaintext
D: One shared IAM role assumed by the app with no user identity
K: A
W: User pools handle sign-up and sign-in (including social), and identity pools exchange tokens for temporary AWS credentials.
X: B=IAM users do not scale to app users. | C=Plaintext passwords are insecure. | D=No per-user identity prevents scoped access.
T: App users and AWS credentials → Cognito user pools plus identity pools.
V: Amazon Cognito

@ SAA-C03 D1 T1.1 applied use-case
S: A company must require MFA for all IAM users who access the AWS console. Which approach enforces this?
A: An IAM policy that denies actions when aws:MultiFactorAuthPresent is false
B: An email reminding users to enable MFA on their accounts each month
C: A CloudWatch dashboard showing which users have MFA devices assigned
D: A bucket policy on every S3 bucket that requires users to use MFA

T: Enforce MFA with IAM condition keys.
V: AWS IAM

@ SAA-C03 D1 T1.1 advanced use-case
S: An application in Account A needs to read objects from an S3 bucket in Account B. Which approach is most secure?
A: A role in Account B that Account A's role can assume, with read access to the bucket
B: Copying all objects nightly from Account B to a bucket in Account A
C: Making the bucket in Account B publicly readable so the application in Account A can read it
D: Sharing an IAM user's access keys from Account B with Account A
K: A
W: Cross-account role assumption grants temporary, scoped access without sharing long-term credentials.
X: B=Copying duplicates data and adds delay. | C=Public access exposes data. | D=Shared keys are long-term credentials.
T: Cross-account access → role assumption.
V: AWS IAM, AWS STS

@ SAA-C03 D1 T1.2 applied use-case
S: A web tier in public subnets and an application tier in private subnets must be isolated so only the web tier can reach the application tier on port 8080. Which control fits?
A: An application tier security group that allows 8080 only from the web tier security group
B: A network ACL that allows all traffic between every subnet in the VPC
C: A route table entry that sends all application tier traffic to the VPC's internet gateway
D: Public IP addresses on the application instances with a firewall script
K: A
W: Security groups can reference other security groups, allowing traffic only from the web tier.
X: B=Allowing all traffic removes isolation. | C=An IGW route makes the tier public. | D=Public IPs expose the tier.
T: Reference security groups to control tier-to-tier traffic.
V: Amazon VPC

@ SAA-C03 D1 T1.2 advanced use-case
S: A public web application needs protection against SQL injection and cross-site scripting at the edge. Which service fits?
A: AWS WAF on CloudFront or the ALB with managed rule groups
B: AWS Shield Standard enabled on the account by default
C: Security groups with inbound rules for port 443 only
D: Network ACLs that block traffic from unknown networks
K: A
W: AWS WAF inspects HTTP requests and blocks attacks such as SQL injection and XSS using managed rules.
X: B=Shield Standard protects against network DDoS, not web exploits. | C=Security groups cannot inspect requests. | D=NACLs filter IP and port only.
T: Web exploits → AWS WAF.

@ SAA-C03 D1 T1.2 applied use-case
S: EC2 instances in private subnets need to call Amazon DynamoDB without internet access. Which solution fits?
A: A DynamoDB gateway VPC endpoint added to the private route tables
B: A NAT gateway in a public subnet for all DynamoDB traffic
C: An internet gateway attached to the private subnets directly
D: Public IP addresses on the instances with a security group
K: A

@ SAA-C03 D1 T1.2 applied use-case
S: A company wants to connect its on-premises network to a VPC quickly over encrypted tunnels using the internet. Which option fits?
A: AWS Site-to-Site VPN
B: AWS Direct Connect
C: VPC peering links
D: An internet gateway
K: A

@ SAA-C03 D1 T1.3 applied use-case
S: A company must encrypt S3 data with keys it manages and see every use of the keys in audit logs. Which option fits?
A: SSE-KMS with a customer managed key
B: SSE-S3 with Amazon S3 managed keys
C: No encryption with bucket versioning
D: S3 Object Lock in governance mode
K: A
W: SSE-KMS with a customer managed key gives control over the key and logs key usage in CloudTrail.
X: B=SSE-S3 keys are managed by S3 with no per-use audit of a customer key. | C=Versioning is not encryption. | D=Object Lock prevents deletion, not encryption.
T: Controlled, auditable S3 encryption → SSE-KMS with a CMK.
V: AWS KMS, Amazon S3

@ SAA-C03 D1 T1.3 advanced use-case
S: A company must keep financial records in S3 unchangeable for seven years, even by the root user. Which configuration fits?
A: S3 Object Lock in compliance mode with a seven-year retention period
B: S3 Versioning with MFA Delete enabled on the bucket by the root user
C: S3 Object Lock in governance mode with a legal hold
D: An IAM policy denying delete actions to all users
K: A
W: Compliance mode prevents anyone, including root, from deleting or overwriting objects during retention.
X: B=Versioning with MFA Delete can still be changed by privileged users. | C=Governance mode can be bypassed with special permissions. | D=IAM policies do not bind the root user.
T: Immutable records even for root → Object Lock compliance mode.
V: Amazon S3

@ SAA-C03 D1 T1.3 applied use-case
S: An RDS database must encrypt data at rest. The database already exists unencrypted. What is the correct approach?
A: Snapshot, copy the snapshot with encryption, and restore from it
B: Enable encryption in place from the RDS console settings
C: Modify the instance class to a type that encrypts by default
D: Enable Multi-AZ, which automatically encrypts the storage
K: A
W: Encryption cannot be enabled on an existing unencrypted instance; restoring from an encrypted snapshot copy creates an encrypted instance.
X: B=In-place encryption is not supported. | C=Instance class does not encrypt. | D=Multi-AZ does not encrypt.
T: Encrypt existing RDS via encrypted snapshot copy.
V: Amazon RDS

@ SAA-C03 D1 T1.1 applied use-case
S: A developer accidentally committed an IAM user's access key to a public repository. What should be done first?
A: Deactivate and rotate the exposed key, then review CloudTrail for misuse
B: Delete the repository and assume the key was not seen by anyone during the exposure
C: Change the IAM user's console password and keep the same key
D: Add MFA to the IAM user and continue using the exposed key
K: A
W: Exposed keys must be disabled immediately, replaced, and their use investigated.
X: B=Deleting the repository does not revoke the key. | C=Password changes do not revoke access keys. | D=MFA does not protect API keys already exposed.
T: Revoke exposed keys immediately and investigate.
V: AWS IAM, AWS CloudTrail
