# SAP-C02 batch 02: Domain 2 (design for new solutions)
@ SAP-C02 D2 T2.1 advanced use-case
S: A company is building a new microservices platform and wants every service deployed through the same pipeline with automated rollback on alarms. Which approach fits?
A: CodePipeline with CodeDeploy blue/green deployments for ECS and CloudWatch alarm-based rollback
B: Developers build container images locally and push them straight to production clusters by hand
C: A nightly cron job on a build server that redeploys every service whether or not it has changed
D: A shared spreadsheet where teams record each deployment and roll back manually when users complain
K: A
W: A standardized pipeline with blue/green deployments and alarm-based rollback gives consistent, safe releases.
X: B=Manual pushes are inconsistent and unsafe. | C=Blind nightly redeploys add risk and lack rollback triggers. | D=Spreadsheets and manual rollback are slow.
T: Standardize deployments with pipelines and automated rollback.
V: AWS CodePipeline, AWS CodeDeploy

@ SAP-C02 D2 T2.1 applied use-case
S: A new application must be deployed identically to 12 Regions with Region-specific parameters. Which solution minimizes operational effort?
A: CloudFormation StackSets with parameter overrides per Region
B: Twelve separate templates edited and deployed by hand in each Region
C: A single template deployed once, relying on the application to replicate itself
D: Manual console setup documented in a wiki page for each Region
K: A
W: StackSets deploy one template to many Regions (and accounts) with per-Region overrides.
X: B=Separate templates drift. | C=Applications do not replicate infrastructure. | D=Manual setup is error-prone.
T: Multi-Region deployments → StackSets.
V: AWS CloudFormation

@ SAP-C02 D2 T2.2 advanced use-case
S: A new payments platform needs RTO under 1 minute and RPO near zero across Regions for a globally distributed user base, with writes accepted in multiple Regions. Which data layer fits?
A: DynamoDB global tables with multi-Region, multi-active writes
B: RDS for MySQL with a cross-Region read replica for failover
C: A single-Region Aurora cluster with daily cross-Region snapshots
D: S3 Cross-Region Replication storing transactions as JSON files
K: A
W: Global tables provide multi-active replication across Regions, enabling near-immediate failover with minimal data loss.
X: B=Promoting a read replica takes longer and loses in-flight writes. | C=Daily snapshots miss the RPO. | D=S3 is not a transactional database.
T: Multi-Region active-active writes → DynamoDB global tables.
V: Amazon DynamoDB

@ SAP-C02 D2 T2.2 applied use-case
S: A new internal application needs DR with an RTO of several hours and the lowest possible cost. Which strategy fits?
A: Backup and restore with backups copied to a second Region
B: Multi-site active-active across two Regions at full scale
C: Warm standby running at 50% of production capacity
D: Pilot light with databases continuously replicated and hot
K: A
W: Backup and restore is cheapest and fits RTOs of hours.
X: B=Active-active is the most expensive. | C=Warm standby costs more than needed. | D=Pilot light costs more than needed for hours of RTO.
T: Hours of RTO at lowest cost → backup and restore.
V: AWS Backup

@ SAP-C02 D2 T2.3 advanced use-case
S: A new multi-tenant SaaS on API Gateway and Lambda must ensure each tenant can access only its own items in a shared DynamoDB table. Which design enforces this?
A: Use tenant ID as partition key and issue scoped credentials with IAM conditions on dynamodb:LeadingKeys
B: Store all tenants' data together and filter results in application code before returning responses
C: Create one IAM user per tenant and embed its access keys in the tenant's client application
D: Encrypt each tenant's items with the same KMS key and rely on encryption for isolation
K: A
W: Scoped credentials with the dynamodb:LeadingKeys condition restrict access to items with the tenant's partition key.
X: B=Application-only filtering is fragile. | C=Embedded keys are insecure and hard to manage. | D=A shared key provides no tenant isolation.
T: Enforce tenant isolation in IAM with LeadingKeys conditions.
V: Amazon DynamoDB, AWS IAM

@ SAP-C02 D2 T2.3 applied use-case
S: A new web application must block common exploits and rate-limit abusive clients at the edge before traffic reaches the origin. Which design fits?
A: CloudFront with an AWS WAF web ACL using managed rules and rate-based rules
B: A security group on the ALB that allows only the company's office IP addresses
C: Network ACLs on the public subnets that deny traffic from all foreign countries
D: An EC2 instance running a custom firewall script that inspects every request
K: A
W: WAF on CloudFront blocks exploits and rate-limits at the edge, protecting the origin.
X: B=Allowing only office IPs blocks real users. | C=NACLs cannot inspect HTTP or rate-limit. | D=A custom firewall instance is a bottleneck and single point of failure.
T: Edge protection → CloudFront plus WAF.
V: AWS WAF, Amazon CloudFront

@ SAP-C02 D2 T2.4 advanced use-case
S: A new event-driven system must process each order exactly once, in order per customer, with high throughput across many customers. Which design fits?
A: SQS FIFO queues using customer ID as the message group ID
B: SQS standard queues with a single consumer processing all messages
C: SNS standard topics fanning out to several Lambda functions in parallel
D: An S3 bucket where orders are uploaded and processed by nightly jobs
K: A
W: FIFO queues preserve order within message groups and deduplicate, while many groups allow parallel throughput.
X: B=Standard queues do not guarantee order, and one consumer limits throughput. | C=Standard SNS does not guarantee order. | D=Nightly batches add delay.
T: Per-key ordering with parallelism → FIFO message groups.
V: Amazon SQS

@ SAP-C02 D2 T2.4 applied use-case
S: A new service must handle unpredictable traffic spikes to 10 times normal load within seconds, without pre-provisioning. Which compute option fits?
A: AWS Lambda behind API Gateway
B: A fixed fleet of EC2 instances
C: A single large EC2 instance
D: An EMR cluster sized for peak
K: A
W: Lambda scales quickly with requests without pre-provisioned capacity.
X: B=A fixed fleet cannot absorb 10x spikes. | C=A single instance cannot scale and is a single point of failure. | D=EMR is for big data processing and would be over-provisioned.
T: Sudden unpredictable spikes → serverless compute.
V: AWS Lambda, Amazon API Gateway

@ SAP-C02 D2 T2.5 advanced use-case
S: A new analytics application needs sub-second queries on terabytes of structured data with complex joins and concurrent dashboards. Which data store fits?
A: Amazon Redshift with concurrency scaling
B: Amazon DynamoDB with global indexes
C: Amazon S3 with S3 Select queries
D: Amazon ElastiCache for Memcached
K: A
W: Redshift is optimized for analytical queries with joins, and concurrency scaling handles many simultaneous dashboards.
X: B=DynamoDB is not built for complex joins. | C=S3 Select filters single objects. | D=Memcached is a cache without SQL analytics.
T: Complex analytical joins at scale → Redshift.
V: Amazon Redshift

@ SAP-C02 D2 T2.5 applied use-case
S: A new mobile game backend needs single-digit millisecond reads and writes for player profiles at any scale. Which database fits?
A: Amazon DynamoDB
B: Amazon Redshift
C: Amazon Athena
D: Amazon Neptune
K: A
W: DynamoDB provides consistent single-digit millisecond performance at virtually any scale.
X: B=Redshift is for analytics. | C=Athena queries S3 data interactively, not low-latency transactions. | D=Neptune is a graph database.

@ SAP-C02 D2 T2.6 advanced use-case
S: A new batch analytics pipeline runs nightly for four hours and can tolerate interruptions with checkpointing. Which compute strategy minimizes cost?
A: Spot Instances with diversified instance types and checkpointing
B: On-Demand Instances launched in a single instance type and size
C: Three-year Reserved Instances for the full nightly capacity
D: Dedicated Hosts reserved for the batch fleet at all times
K: A
W: Interruption-tolerant, checkpointed workloads benefit most from Spot pricing with diversified capacity.
X: B=On-Demand costs more. | C=Reservations for four hours a day waste capacity. | D=Dedicated Hosts are expensive.
T: Interruptible batch → Spot with checkpointing.
V: Amazon EC2

@ SAP-C02 D2 T2.6 applied use-case
S: A new application stores large media files that are accessed frequently for 30 days and rarely afterward, but must be retrievable within milliseconds when needed. Which storage design minimizes cost?
A: S3 Standard with a lifecycle rule to S3 Glacier Instant Retrieval after 30 days
B: S3 Standard for all files for the entire life of the application
C: S3 Glacier Deep Archive immediately after upload for every file
D: EBS gp3 volumes attached to the application servers for all files
K: A
W: Lifecycle transitions to Glacier Instant Retrieval cut cost for rarely accessed data while keeping millisecond access.
X: B=Standard is costly for rarely accessed data. | C=Deep Archive retrieval takes hours. | D=EBS is more expensive and not shared.
T: Rare access but instant retrieval → Glacier Instant Retrieval via lifecycle.
V: Amazon S3

@ SAP-C02 D2 T2.1 applied use-case
S: A new application requires infrastructure definitions reviewed in pull requests, tested, and applied automatically on merge. Which TWO components are needed? (Select TWO)
A: Infrastructure as code stored in a version-controlled repository
B: A CI/CD pipeline that validates and deploys changes on merge
C: A shared administrator account used for console changes
D: A manual approval by email for every small change
E: Screenshots of the console saved in a shared folder
K: A,B
W: IaC in version control enables reviews, and a pipeline validates and applies changes consistently.
X: C=Shared console access bypasses review. | D=Email approvals are slow and untracked. | E=Screenshots are not deployable.
T: GitOps = IaC in version control plus automated pipelines.
V: AWS CodePipeline, AWS CloudFormation

@ SAP-C02 D2 T2.3 advanced use-case
S: A new data platform must encrypt all data with keys that are automatically rotated and whose usage is logged, and separate duties between key administrators and data users. Which approach fits?
A: KMS customer managed keys with automatic rotation and key policies separating administrators from users
B: SSE-S3 managed keys for all buckets, with bucket policies restricting who can read the data
C: A single KMS key shared by all teams, with every developer granted full key administration
D: Client-side encryption with keys stored in a text file inside the application code repository
K: A
W: Customer managed keys support rotation, CloudTrail logging, and key policies that separate administration from usage.
X: B=SSE-S3 does not provide key policy control or separation of duties. | C=Full admin for all developers defeats separation. | D=Keys in code are insecure.
T: Separation of duties and auditability → KMS CMKs with key policies.
V: AWS KMS

@ SAP-C02 D2 T2.4 applied use-case
S: A new API must remain available if an entire Region fails, with traffic automatically shifted. Which TWO components fit? (Select TWO)
A: Deployments of the API in two Regions
B: Route 53 failover or latency routing with health checks
C: A single Region deployment with more Availability Zones
D: One NAT gateway shared by both Regions' private subnets
E: A larger instance type in the primary Region only
K: A,B
W: Multi-Region deployments plus health-checked DNS routing shift traffic away from a failed Region.
X: C=More AZs do not survive a Regional failure. | D=NAT gateways are zonal and not shared across Regions. | E=Larger instances do not add Regional redundancy.
T: Survive Regional failure with multi-Region deployment and health-checked routing.
V: Amazon Route 53

@ SAP-C02 D2 T2.5 advanced tradeoff
S: A new application needs a relational database with read scaling to 15 replicas and storage that grows automatically to 128 TiB. Which option fits?
A: Amazon Aurora
B: Amazon RDS for SQL Server Express
C: Amazon DynamoDB
D: Amazon Keyspaces
K: A
W: Aurora supports up to 15 low-latency replicas and storage that grows automatically to 128 TiB.
X: B=SQL Server Express has small storage limits and limited replicas. | C=DynamoDB is not relational. | D=Keyspaces is Cassandra-compatible, not relational.

@ SAP-C02 D2 T2.2 applied use-case
S: A new application on ECS must keep running if one Availability Zone fails, without manual intervention. Which configuration fits?
A: Spread tasks across at least two AZs behind an ALB with service auto scaling
B: Run all tasks in one AZ and back up task definitions to S3 every hour
C: Use a single task with a larger CPU and memory reservation in one AZ
D: Place the ALB in one AZ and the tasks in a different single AZ
K: A
W: Multi-AZ task placement with load balancing and auto scaling tolerates an AZ failure.
X: B=Single-AZ tasks fail with the AZ. | C=One task is a single point of failure. | D=Single-AZ components fail with their AZ.
T: Spread containers across AZs behind a load balancer.
V: Amazon ECS

@ SAP-C02 D2 T2.6 advanced use-case
S: A new internal API receives about 50 requests per hour with occasional bursts. The company wants the lowest cost with no servers to manage. Which design fits?
A: API Gateway HTTP API with Lambda
B: An ALB with two always-on EC2 instances
C: An NLB with a fixed Auto Scaling group
D: An EKS cluster with three worker nodes
K: A
W: Serverless pay-per-request services cost little at low volume and scale for bursts.
X: B=Always-on instances cost more at low volume. | C=A fixed fleet costs more at low volume. | D=EKS clusters have fixed control plane and node costs.
T: Low, bursty traffic → serverless pay-per-request.
V: Amazon API Gateway, AWS Lambda
