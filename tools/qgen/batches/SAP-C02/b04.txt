# SAP-C02 batch 04: Domain 4 (migration and modernization)
@ SAP-C02 D4 T4.1 applied use-case
S: A company must plan migration of 800 on-premises servers and needs utilization data and dependency maps to group applications into waves. Which service helps collect this data?
A: AWS Application Discovery Service with agents or agentless collectors
B: AWS Trusted Advisor checks run against the on-premises data center servers
C: Amazon Inspector scans of the on-premises servers over the public internet
D: AWS Cost Explorer reports generated from the current on-premises invoices
K: A
W: Application Discovery Service gathers server specs, utilization, and network dependencies to plan migration waves.
X: B=Trusted Advisor checks AWS accounts. | C=Inspector does not map dependencies for planning. | D=Cost Explorer covers AWS spending.
T: Discovery and dependency mapping → Application Discovery Service.
V: AWS Application Discovery Service

@ SAP-C02 D4 T4.2 applied use-case

A: AWS Application Migration Service
B: AWS Database Migration Service
C: AWS Schema Conversion Tool
D: AWS DataSync scheduled tasks
K: A

@ SAP-C02 D4 T4.2 advanced use-case
S: A company is migrating an on-premises Oracle database to Aurora PostgreSQL with minimal downtime. Which combination fits?
A: AWS SCT to convert the schema and code, then AWS DMS with full load and CDC
B: A single DMS full-load task during a weekend with the application offline
C: Export Oracle tables to CSV, copy them to S3, and import them manually
D: Application Migration Service replicating the Oracle server to EC2 only
K: A
W: SCT converts schema and procedural code for heterogeneous migrations, and DMS with change data capture keeps data in sync until cutover.
X: B=Full load alone needs long downtime. | C=Manual CSV exports are slow and error-prone. | D=Rehosting keeps Oracle rather than migrating to Aurora.
T: Heterogeneous DB migration → SCT plus DMS with CDC.
V: AWS DMS, AWS SCT

@ SAP-C02 D4 T4.2 applied use-case
S: A company needs to transfer 500 TB of archival data to S3 within two weeks, but its internet link is only 1 Gbps. Which option fits?
A: AWS Snowball Edge devices
B: AWS DataSync over the internet
C: S3 Transfer Acceleration uploads
D: Site-to-Site VPN file copies
K: A
W: At 1 Gbps, 500 TB would take well over a month online; Snowball devices move it offline much faster.
X: B=DataSync is limited by the link speed. | C=Transfer Acceleration is still limited by bandwidth. | D=VPN copies are limited by the link.
T: Very large transfers over slow links → Snowball.
V: AWS Snowball

@ SAP-C02 D4 T4.3 advanced use-case
S: A migrated monolith on EC2 must be broken into services gradually without disrupting users. Which approach fits?
A: The strangler fig pattern, routing specific paths to new services behind the same entry point
B: Rewrite the entire application at once in a new codebase and switch all traffic over on a single weekend
C: Freeze all feature work for two years while a separate team rebuilds the system
D: Duplicate the monolith for each new feature and let users choose which one to use

@ SAP-C02 D4 T4.3 advanced use-case
S: A company migrating to AWS needs to connect on-premises applications to new AWS services during a multi-year hybrid period, with consistent low latency. Which design fits?
A: Redundant Direct Connect links with a transit gateway hub connecting VPCs
B: Public internet connections with application-level encryption only
C: A single Site-to-Site VPN connection to one VPC for all traffic
D: Temporary data exports copied to S3 each night for all integrations
K: A
W: Redundant Direct Connect provides consistent, private, low-latency hybrid connectivity, and a transit gateway reaches many VPCs.
X: B=The internet is not consistent in latency. | C=A single VPN is a single point of failure with variable latency. | D=Nightly exports do not support live integration.
T: Long hybrid periods need redundant, consistent connectivity.
V: AWS Direct Connect, AWS Transit Gateway

@ SAP-C02 D4 T4.4 applied use-case
S: A company wants to modernize a batch job that runs on an always-on EC2 instance for 20 minutes each hour. Which approach reduces cost and operations?
A: Run the job as a scheduled AWS Batch job on Fargate or as a scheduled container task
B: Move the job to a larger EC2 instance type that is also kept running 24/7 for faster completion
C: Run the job manually each hour from an engineer's laptop instead
D: Keep the instance running and purchase a Reserved Instance for it
K: A
W: Scheduled serverless or managed batch execution removes idle capacity and server management.
X: B=Larger always-on instances cost more. | C=Manual execution is unreliable. | D=Reservations still pay for idle time.
T: Replace idle always-on batch hosts with scheduled managed execution.

@ SAP-C02 D4 T4.2 advanced use-case
S: Which TWO actions reduce cutover risk when migrating a critical database with DMS? (Select TWO)
A: Validate data with DMS data validation before cutover
B: Keep CDC running until the application switches over
C: Stop the source database before the full load starts
D: Skip testing so the cutover happens sooner
E: Delete the source immediately after full load
K: A,B
W: Validation confirms data consistency, and ongoing CDC keeps the target in sync until a short cutover.
X: C=Stopping the source creates long downtime. | D=Skipping tests adds risk. | E=Deleting the source removes rollback.
T: Validate and keep replicating until cutover.
V: AWS DMS

@ SAP-C02 D4 T4.4 advanced use-case
S: A company wants to modernize a tightly coupled monolith's reporting feature, which runs heavy SQL queries against the production database. Which approach improves both performance and modernization?
A: Stream changes to an analytics store and serve reports from it, separate from the transactional database
B: Add more indexes to every production table so that the heavy reporting queries run faster on the same database
C: Schedule reports during business hours to spread load throughout the day
D: Move the entire monolith to a larger database instance with more memory
K: A
W: Separating analytics from transactions (for example, CDC into an analytics store) removes contention and modernizes the architecture.
X: B=Excessive indexes slow writes and do not separate workloads. | C=Business-hours reporting increases contention. | D=Scaling up delays but does not fix the coupling.
T: Separate analytical workloads from transactional databases.
V: AWS DMS, Amazon Redshift
