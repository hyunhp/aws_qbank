# SAP-C02 batch 06: Domain 2 (design for new solutions), continued
@ SAP-C02 D2 T2.1 applied use-case
S: A new serverless application needs repeatable deployments of Lambda functions, API Gateway, and DynamoDB tables with local testing support. Which tool fits?
A: AWS Serverless Application Model (SAM)
B: AWS Elastic Beanstalk with a web server tier
C: Manual console configuration for each resource
D: AWS OpsWorks stacks with Chef recipes
K: A
W: SAM defines serverless resources concisely, deploys through CloudFormation, and supports local testing.
X: B=Beanstalk targets server-based web apps. | C=Manual configuration is not repeatable. | D=OpsWorks targets server configuration management.
T: Serverless IaC with local testing → SAM.
V: AWS SAM

@ SAP-C02 D2 T2.1 advanced use-case
S: A new application on EKS must be deployed with progressive delivery, shifting traffic gradually and rolling back on metrics. Which approach fits?
A: A GitOps controller with canary rollouts driven by metrics, such as Argo Rollouts
B: kubectl apply commands run manually from a laptop for each production release
C: Deleting all pods and recreating them at once for every new application version
D: Deploying to production only once a year to minimize the risk of each release
K: A
W: Progressive delivery tools shift traffic gradually and roll back automatically based on metrics.
X: B=Manual commands are error-prone. | C=Recreating all pods causes downtime. | D=Rare releases increase batch risk.
T: Use progressive delivery with automated rollback on Kubernetes.
V: Amazon EKS

@ SAP-C02 D2 T2.2 advanced use-case
S: A new application requires RTO of 15 minutes and RPO of 1 minute in a second Region at moderate cost. Which DR strategy fits?
A: Warm standby with continuous data replication and scaled-down compute in the second Region
B: Backup and restore with daily backups copied to the second Region for recovery
C: Pilot light with data replicated but no compute provisioned at all in the Region
D: Multi-site active-active running at full production capacity in both Regions at all times
K: A
W: Warm standby keeps replicated data and running scaled-down compute, meeting minutes of RTO at moderate cost.
X: B=Daily backups miss the RPO and RTO. | C=Provisioning all compute during failover may exceed 15 minutes. | D=Active-active costs more than required.
T: Minutes of RTO at moderate cost → warm standby.

@ SAP-C02 D2 T2.2 applied use-case
S: A new application stores critical files in S3 and must survive Regional failure with a replication SLA. Which feature fits?
A: S3 Cross-Region Replication with Replication Time Control
B: S3 Same-Region Replication with versioning
C: S3 Lifecycle transitions to Glacier Deep Archive after 30 days
D: S3 Object Lambda access points per application
K: A

@ SAP-C02 D2 T2.3 advanced use-case

@ SAP-C02 D2 T2.3 applied use-case

@ SAP-C02 D2 T2.4 applied use-case
S: A new application sends notifications to email, SMS, and mobile push, and several internal services must also receive each event. Which pattern fits?
A: SNS topic fan-out to SQS queues and delivery endpoints
B: A single SQS queue read by every consuming service
C: Direct synchronous calls to each service and channel
D: A shared database table polled by each consumer
K: A
W: SNS fan-out delivers each event to multiple subscribers, including queues and notification channels.
X: B=One queue delivers each message to a single consumer. | C=Synchronous calls couple services. | D=Polling tables is inefficient.
T: One event, many consumers → SNS fan-out.
V: Amazon SNS, Amazon SQS

@ SAP-C02 D2 T2.4 applied use-case
S: A new application must continue accepting user uploads even if downstream processing is down for hours. Which design fits?
A: Store uploads in S3 and queue processing events in SQS
B: Process uploads synchronously in the upload request
C: Keep uploads in the web server's memory until processed
D: Reject uploads whenever the processing service is down
K: A
W: Durable storage plus a queue decouples intake from processing, so uploads continue during outages.
X: B=Synchronous processing fails when downstream is down. | C=Memory is lost on restarts. | D=Rejecting uploads harms users.
T: Decouple intake from processing with durable storage and queues.
V: Amazon S3, Amazon SQS

@ SAP-C02 D2 T2.6 applied use-case

@ SAP-C02 D2 T2.6 advanced tradeoff
