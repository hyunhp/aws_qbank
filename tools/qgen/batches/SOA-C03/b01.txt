# SOA-C03 batch 01: Domain 1 (monitoring, logging, remediation, performance)
@ SOA-C03 D1 T1.1 applied use-case
S: An operations team needs memory utilization metrics for its EC2 instances in CloudWatch, but the metric does not appear by default. What should they do?
A: Install and configure the CloudWatch agent on the instances
B: Enable detailed monitoring on each instance in the EC2 console
C: Turn on VPC Flow Logs for the subnets hosting the instances
D: Create a CloudTrail trail that records all EC2 API activity
K: A
W: Memory and disk space are OS-level metrics; the CloudWatch agent collects and publishes them. Detailed monitoring only increases the frequency of default metrics.
X: B=Detailed monitoring gives 1-minute default metrics but not memory. | C=Flow Logs capture network traffic metadata. | D=CloudTrail records API calls, not OS metrics.
T: OS-level metrics such as memory require the CloudWatch agent.
V: Amazon CloudWatch

@ SOA-C03 D1 T1.1 advanced use-case
S: A team wants an alarm only when both CPU is above 80% and the ALB 5XX count is elevated, to reduce noisy pages. Which CloudWatch feature fits?
A: A composite alarm combining the two alarms with AND
B: A metric filter on the application log group only

@ SOA-C03 D1 T1.1 applied use-case

C: A log group retention policy of five minutes

@ SOA-C03 D1 T1.1 advanced troubleshooting

@ SOA-C03 D1 T1.2 advanced troubleshooting
S: An EC2 instance fails its system status check but passes its instance status check. What is the most appropriate first action?
A: Stop and start the instance to move it to healthy hardware
B: Reboot the operating system from within the instance
C: Increase the size of the root EBS volume on the instance
D: Update the security group to allow all inbound traffic
K: A
W: System status check failures indicate problems with underlying AWS infrastructure; stopping and starting (for EBS-backed instances) moves the instance to new hardware.
X: B=A reboot keeps the same host. | C=Disk size is not the issue. | D=Security groups are unrelated to status checks.
T: System check failure → stop/start (or automate recovery).
V: Amazon EC2

@ SOA-C03 D1 T1.2 applied use-case

@ SOA-C03 D1 T1.3 advanced use-case

@ SOA-C03 D1 T1.3 applied use-case
S: A read-heavy web application's RDS database is overloaded by repeated identical queries. Which change most reduces database load?
A: Add an ElastiCache layer to cache frequent query results
B: Increase the database's backup retention to 35 days
C: Enable Multi-AZ to add a synchronous standby replica
D: Move the database to a smaller instance class to save cost
K: A
W: Caching frequent reads in ElastiCache serves repeated queries from memory, reducing database load.
X: B=Backup retention does not affect load. | C=Multi-AZ standby does not serve reads (for instance deployments). | D=A smaller instance worsens performance.
T: Offload repeated reads with a cache.
