# SOA-C03 batch 06: Domain 1 (monitoring and performance), continued
@ SOA-C03 D1 T1.1 applied use-case
S: An application publishes a custom metric that needs one-second granularity for alarms on short spikes. What should the team use?
A: High-resolution custom metrics with a 10-second alarm period
B: Standard-resolution metrics aggregated every five minutes
C: CloudTrail data events on the application's API calls
D: VPC Flow Logs aggregated at one-minute intervals
K: A
W: High-resolution custom metrics store data at one-second granularity, and alarms on them can evaluate periods as short as 10 seconds.
X: B=Five-minute aggregation hides short spikes. | C=CloudTrail records API calls, not custom metrics. | D=Flow Logs capture network traffic, not app metrics.
T: Short spikes need high-resolution metrics.
V: Amazon CloudWatch

@ SOA-C03 D1 T1.2 applied troubleshooting
S: An EC2 instance's CPU credit balance drops to zero each afternoon and performance falls. The instance is a t3.medium in standard mode. What is a good fix?
A: Switch to unlimited mode or move to a fixed-performance instance type
B: Increase the size of the instance's root EBS volume by 50 percent
C: Attach an Elastic IP address to the instance's primary interface
D: Enable detailed monitoring to publish metrics every minute instead
K: A
W: Burstable instances throttle when credits run out; unlimited mode or a non-burstable type sustains higher CPU.
X: B=Disk size does not affect CPU credits. | C=Elastic IPs do not affect performance. | D=Monitoring frequency does not add CPU.
T: Credit exhaustion on T instances → unlimited mode or a different type.
